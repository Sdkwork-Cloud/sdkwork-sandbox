# Service Host Component Contract

`component.spec.json` is the machine authority for the future L5 composition root. No executable composition is declared in Phase 0.

`sandbox-service-host-composition.contract.json` is the draft candidate contract for `SandboxServiceHostConfig`, injected dependencies, standalone/cloud parity, fail-closed `SandboxServiceHostReadiness`, bounded idempotent shutdown, and cross-contract Profile/Capability gates. It requires the common Workspace Runtime Transaction gate, Local Host Boundary plus Standalone Data Residency evidence for `standalone/local`, the cold microVM dependency set for Firecracker, additional Node Trust/Admission/Capacity gates for `cloud/firecracker`, and an explicit optional Runtime Pool overlay. Command and Terminal require an executor plus conformance evidence; a Provider descriptor alone is insufficient. It sets `implementationAuthorized` to `false`; it is review evidence, not authority to add public exports, config keys, runtime entrypoints, Provider implementations, API/SDK surfaces, Secret/KMS wiring, scheduling, or deployment profiles.

`sandbox-service-host-bootstrap.contract.json` is the matching draft bootstrap boundary. It fixes the eight source profile IDs, safe normalized config, preopened `SandboxRuntimeDirectoryCapabilities`, bounded Secret/KMS adapters, external PostgreSQL composition with repository-only injection, explicit Redis disablement, bounded/redacted Telemetry, separate Audit/Outbox readiness, fixed failure-atomic bootstrap and reverse shutdown ordering, and candidate ownership decisions. It does not authorize `etc/`, database/cache, Secret/KMS, Telemetry/Outbox, runtime or deployment materialization.
